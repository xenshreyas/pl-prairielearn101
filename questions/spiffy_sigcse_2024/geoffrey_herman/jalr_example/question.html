Background Information ---------------------- We provide a simplified version of the MIPS datapath that you will need to modify to provide support for a new instruction. We've removed support for instructions like `nor`, `xor`, `lui`, `j`, `bne`, `lbu`, and `sb` so that you have fewer control signals to worry about. Likewise, we moved support for `slt` into the ALU. single\_cycle.pdf We have also simplified the ALU and provide the following defined constants for accessing your ALU. \`define ALU\_ADD 3'h0 \`define ALU\_SUB 3'h1 \`define ALU\_AND 3'h2 \`define ALU\_OR 3'h3 \`define ALU\_SLT 3'h4 The MIPS\_green\_sheet.pdf and MIPS Reference Guide are available for your reference as well. Instructions ------------ Add support for the `jalr` instruction to the MIPS datapath (specification below). jalr rs Jump and Link Register r\-type opcode: 6'h00 funct: 6'h09 \`define OP0\_JALR 6'h09 # You will want to copy this line into machine.v. R\[31\] \= PC + 4 PC \= R\[rs\] Compiling, Testing, and Debugging --------------------------------- 1. Read the prompt and figure out how you think `test.s` should behave 2. Take some time to sketch out the changes you want to make on paper first 3. Make a copy of the original `machine.v` (and any other Verilog file that you change), so you can undo any changes that break everything. You have the `Reset` button on the workspace in the worst-case scenario 4. Run make regression make > regress to create a file called `regress`. The regression tests will help you make sure that you didn't break the original functionality of the datapath. 5. modify `machine.v` to implement the changes you drew on paper. Don't modify any other files as your copy of those files will be replaced by our copies of them. 6. Run make test make to run your Verilog against the test input that has your instruction. If the results are not what you expected them to be from step 1, then we suggest firing up the vcd viewer (recommend just clicking to open (i.e., don't right click and choose waveform viewer) as there are too many signals for the waveform viewer to handle) to trace down your errors, especially if you are getting X's or Z's in register values. Start by looking at the values going into the register file and trace them backward until you find the first spot where they go bad. It can be useful to compare your modified code with your original code using diff machine.v orig\_machine.v (where `orig_machine.v` is whatever you called the copy you made earlier). 7. when your test input is working, run: make regression make > regress.new diff regress.new regress like before, this will run the regression test, but in addition compare your new results to what they should be. Fix any bugs. 8. If you want to write your own test cases, edit `custom.s` and then run make custom make 9. Celebrate! #### Workspace Test and debug your code in the workspace before submitting!
