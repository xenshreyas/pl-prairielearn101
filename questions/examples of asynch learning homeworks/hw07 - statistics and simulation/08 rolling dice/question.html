Probability distributions, such as the _Normal Distribution_ we saw earlier, aren't too bad if there is only one. But if you are working with a system that has multiple random variables (which is true of many systems!), then trying to find a probability distribution that covers all the random variables quickly becomes impossible. So. **Probability is hard -- but vectorization is easy!** We can use MATLAB to pick values for each random variable individually and calculate the overall outcomes by combining them together. If we do this over and over, and we do it enough times, we can see how systems work for different ranges of input data, even if we can't figure out the math equation for the overall probabilities. Let's look at an example. #### Example: Rolling Dice If you roll one 6-sided die 10 times, you will get 10 different numbers that are in the range 1-6: These rolls of the die can be represented by a vector in MATLAB: Therefore, we can use the `randi` function to simulate rolling a die. For a 6-sided die, `imax` = 6 in the call to `randi`. Here are examples for rolling the die 10 times, 5 times, and 8 times: Say we have two 6-sided dice and we wanted to know the probability that the sum of the two dice is greater than 7. We could figure this out using math, but this isn't a math class. Let's use simulation instead! Here is an algorithm that we can use to solve this problem: 1. Use `randi` to generate a row vector that represents 1,000 rolls of one die. 2. Use `randi` to generate another row vector that represents 1,000 rolls of the other die. 3. Add the row vectors together to get the sum of the dice for each of the 1,000 rolls. 4. Use the "Counting Elements That Match" Common Pattern from the homework assignment on logical indexing to identify the locations of the sums that are greater than 7 and count them. 5. Divide by 1,000 to get the percentage of sums that are greater than 7. 6. Display the percentage - this is the probability that the sum will be greater than 7. If we're looking to get the same answer to at least three significant figures, then this range of answers isn't really good enough. What do we do now?? Simulation has random processes/variables at its base; this means, by definition, that you get different answers from the randomness. Therefore, a key metric in simulation is **convergence** -- when you have simulated enough random data so that you get the same answer each time you run the simulation. For this example of rolling the two dice, we just need to roll the dice so many times that we get the same probability each time, within a certain number of significant figures. If we increase the number of rolls to 5000 by changing the script (or creating a new version of the script, such as `RollingTwoRegularDiceMoreRolls.m` ) and re-running the script, we can see if our answer starts to _converge_ : \>> RollingTwoRegularDiceMoreRolls The probability that the sum of the two dice rolls will be greater than 7 is: 0.405. >> RollingTwoRegularDiceMoreRolls The probability that the sum of the two dice rolls will be greater than 7 is: 0.4226. >> RollingTwoRegularDiceMoreRolls The probability that the sum of the two dice rolls will be greater than 7 is: 0.4124. >> RollingTwoRegularDiceMoreRolls The probability that the sum of the two dice rolls will be greater than 7 is: 0.415. >> RollingTwoRegularDiceMoreRolls The probability that the sum of the two dice rolls will be greater than 7 is: 0.4242. >> RollingTwoRegularDiceMoreRolls The probability that the sum of the two dice rolls will be greater than 7 is: 0.4048. Now our answers have a range of 0.4050 to 0.4242. This is a **narrower range than before, so our answers are starting to converge**, yay!
